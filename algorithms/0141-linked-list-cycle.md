## 题目

给你一个链表的头节点 `head`，判断链表中是否有环。

如果链表中有某个节点，可以通过连续跟踪 `next` 指针再次到达，则链表中存在环。

```
输入：head = [3,2,0,-4], pos = 1     （尾部连到下标 1）
输出：true
```

> 注意：函数签名里没有 `pos`，环是真实存在于链表结构里的，不能靠值判断。

---

## 我的第一版（11/16）：四个 bug 全中

```java
public boolean hasCycle(ListNode head) {
    ListNode fast = new ListNode();          // ① 编译不过
    ListNode slow = new ListNode();
    fast = slow.next = head;                 // ② 两个指针都指向 head
    while (fast.next != null && slow.next != null) {
        if (fast == slow) { return true; }   // ③ 恒成立
    }                                        // ④ 没有移动 → 死循环
    return false;
}
```

### 逐个拆

| # | bug | 后果 |
|---|---|---|
| 1 | **`new ListNode()`** | 本题 `ListNode` 只有 `ListNode(int x)` 这一个构造器，**没有无参构造 → 编译不过** |
| 2 | **`fast = slow.next = head`** | Java 链式赋值从右往左：先 `slow.next = head`，再 `fast = slow.next` → **两个都等于 head** |
| 3 | 两指针重合，`fast == slow` 恒真 | **长度 ≥ 2 的无环链表全部返回 true** |
| 4 | 循环体里没有 `fast = fast.next.next` | **死循环** |

### 根因

**不是思路错，是模板没记牢。**

三个必须记住的点，全丢了一半：

```
① 都从 head 开始，不要 new 任何节点
② fast 走两步，slow 走一步
③ 先移动，再比较
```

> 顺带：第 2 条的链式赋值是 Java 陷阱——**从右往左求值**，写在一起的两个赋值会互相影响。

## 正确写法（11/17 一次写对）

```java
public class Solution {
    public boolean hasCycle(ListNode head) {
        ListNode fast = head;
        ListNode slow = head;

        while (fast != null && fast.next != null) {   // ★ 顺序不能反
            slow = slow.next;                          // 慢的走一步
            fast = fast.next.next;                     // 快的走两步

            if (fast == slow) return true;             // ★ 先移动，再比较
        }
        return false;
    }
}
```

### 复杂度

| 项 | 值 |
|---|---|
| 时间 | **O(n)** |
| 空间 | **O(1)** —— 两个指针 |

---

## ★ 三个关键点

### ① 都从 `head` 开始，不要错开

有人会想「让 `fast = head.next` 先错开一位」。**这题不需要。**

错开的话，单节点无环的 case 会出问题（`fast.next` 是 null 时的处理变复杂）。

**都从 head 开始最简单，因为循环体的第一步就会把它们拉开。**

### ② 循环条件 `fast != null && fast.next != null` 的顺序不能反

```java
while (fast != null && fast.next != null)      // ✅
while (fast.next != null && fast != null)      // ❌ NPE
```

**Java 的 `&&` 短路求值**：`fast == null` 时，第一个条件为 false，**不会去读 `fast.next`**。

反过来写，`fast` 为 null 时先读 `fast.next` → **空指针异常**。

> 这也是「删一行测试」的实例：这两个条件单看都对，**顺序才决定会不会崩。**

### ③ 先移动，再比较

```java
while (...) {
    slow = slow.next;      // ← 先动
    fast = fast.next.next;
    if (fast == slow) ...  // ← 再比
}
```

**如果先比较再移动**：第一轮两个都指向 `head`，`fast == slow` 直接为 true → **所有链表都判成有环**。

这和我第一版的 bug 3 是同一个原因，只是形式不同。

---

## ★ 为什么「有环必相遇」

这是面试最爱追问的点，答「因为有环」不算。

### 说法一：相对速度

```
slow 每次走 1，fast 每次走 2
→ 相对速度 = 1

只要两者都进了环，fast 就在以每轮 1 步的速度逼近 slow，
在环里绕圈，迟早会踩到 slow 的位置。
```

**关键**：相对速度恒为 1，距离每轮缩小 1，**必然会到 0**。

### 说法二：跑道

想象两人在**环形跑道**上跑，一个速度是另一个的两倍。

- 都在跑道上（都进环了）→ **快的必然从后面追上慢的**
- 一个先跑完离开跑道（走到 null）→ **说明没环**

### 为什么「无环必先到尽头」

无环时，`fast` 每轮前进 2，一定比 `slow` 先撞到 `null`。

**两种情况的判断互斥**，所以 `return false` 不会误判。

> 补充追问：「为什么 slow 走 1、fast 走 2，而不是走 3？」
> 走 2 相对速度是 1，**一定能追上**；走 3 相对速度 2，如果 slow 在环里、环长是偶数，**可能"跳过"** slow 而不相遇。**走 2 是最小且保证相遇的速度。**

## 易错点清单

| # | 坑 | 后果 |
|---|---|---|
| 1 | `new ListNode()` | 本题无无参构造 → 编译不过 |
| 2 | `fast = slow.next = head` | 链式赋值从右往左 → 两指针重合 |
| 3 | 条件顺序写成 `fast.next != null && fast != null` | **NPE** |
| 4 | 先比较后移动 | 首轮恒相等 → **所有链表判为有环** |
| 5 | 循环体没有移动语句 | 死循环 |
| 6 | `fast` 一次走 3 步 | 可能跳过 `slow`，不相遇 |

## 手推验证

`[3, 2, 0, -4]`，尾部连回下标 1（值 2）

| 轮 | slow | fast | 相等? |
|---|---|---|---|
| 初始 | 3 | 3 | — |
| 1 | 2 | 0 | 否 |
| 2 | 0 | 2（-4 → 2） | 否 |
| 3 | -4 | -4（2 → 0 → -4） | **是** ✅ |

**返回 true。**

### 无环的例子

`[1, 2]` 无环

| 轮 | slow | fast |
|---|---|---|
| 初始 | 1 | 1 |
| 1 | 2 | null |
| 判断 | — | `fast == null` → **退出，返回 false** ✅ |

## 一句话总结

> **快慢指针：都从 head 起，fast 走两步、slow 走一步，先动后比。**
> **有环必相遇（相对速度 1），无环必先到尽头。**
