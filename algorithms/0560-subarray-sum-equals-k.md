## 题目

给你一个整数数组 `nums` 和一个整数 `k`，请你统计并返回该数组中**和为 `k` 的子数组**的个数。

```
输入：nums = [1,1,1], k = 2
输出：2
解释：子数组 [1,1] 出现两次

输入：nums = [1,-1,1], k = 1     ← 有负数，滑窗救不了
输出：3
```

---

## 我的第一版（方向错：用了滑动窗口）

```java
public int subarraySum(int[] nums, int k) {
    int count = 0, sum1 = 0;
    for (int i = 0; i < nums.length; i++) {
        while (sum1 < k) {
            sum1 += nums[i];        // ❌ i 在 while 里不变，会死循环
        }
        if (sum1 == k) { count++; sum1 = 0; }
        else if (sum1 > k) { sum1 = 0; }
    }
    return count;
}
```

### 两个问题

| # | 问题 | 后果 |
|---|---|---|
| 1 | **用滑动窗口解这道题** | 有负数时单调性失效，窗口该缩还是该扩无法判断 |
| 2 | `while (sum1 < k) sum1 += nums[i]` | `i` 不变，`nums[i]` 每次一样 → **`[0], k=1` 死循环** |

---

## ★ 关键洞察一：为什么滑窗不成立

**滑动窗口成立的前提：窗口变大，和也单调变大（或变小）。**

这只有在**数组全为正**时才成立。

```
nums = [1, -1, 1], k = 1
```

`right` 右移一格，和可能**变小**。于是"和太大就缩左边"这条路断了——**你不知道该缩哪边**。

### 判据

> **题目里允许负数 → 滑窗不适用 → 直接想前缀和。**

### 对比 209 题（长度最小的子数组）

| | 209 长度最小的子数组 | **560 和为 K 的子数组** |
|---|---|---|
| 数组约束 | **全为正** | **可能有负数** |
| 解法 | **滑动窗口** | **前缀和 + 哈希** |
| 单调性 | 有 | **没有** |

**同样是「子数组」，一个用滑窗一个用前缀和——差别只在「有没有负数」。**

---

## ★ 关键洞察二：这题就是两数之和

### 推导

```
子数组 [j+1 .. i] 的和 = pre[i] - pre[j]

要它等于 k：
    pre[i] - pre[j] = k
→   pre[j] = pre[i] - k
```

**所以遍历到 `i` 时，只要问一句：`pre[i] - k` 这个前缀和，之前出现过几次？**

### 和两数之和的映射

| | [0001] 两数之和 | **560 和为 K 的子数组** |
|---|---|---|
| 找什么 | `target - nums[i]` | `pre[i] - k` |
| 在哪儿找 | 之前出现过的**值** | 之前出现过的**前缀和** |
| 存什么 | `值 → 下标` | `**前缀和 → 出现次数**` |
| 结构 | 遍历，查表 | 累加，查表 |

**同一个套路：把「枚举组合」换成「查表找另一半」。**

> 注意存的是**次数**，不是下标——因为问的是"可以结束在这儿的子数组有几个"。

---

## 正确解法

```java
class Solution {
    public int subarraySum(int[] nums, int k) {
        Map<Integer, Integer> map = new HashMap<>();
        map.put(0, 1);              // ★ 空前缀：最容易漏的一行

        int pre = 0, count = 0;
        for (int x : nums) {
            pre += x;
            count += map.getOrDefault(pre - k, 0);   // 找「另一半」
            map.merge(pre, 1, Integer::sum);         // 记下当前前缀和
        }
        return count;
    }
}
```

### 复杂度

| 项 | 值 |
|---|---|
| 时间 | **O(n)** —— 每个元素一次查表 + 一次插入 |
| 空间 | **O(n)** —— 最多 n 个不同的前缀和 |

---

## ★ 最容易漏的一行：`map.put(0, 1)`

**不写这行，所有「从头开始」的子数组全部漏掉。**

以 `nums = [1, 1, 1]`, `k = 2` 为例：

| 步 | 元素 | pre | 查 `pre-2` | 有 `put(0,1)` | 没有 |
|---|---|---|---|---|---|
| 初始 | — | 0 | — | map `{0:1}` | map `{}` |
| 1 | 1 | 1 | 查 -1 → 0 | count=0 | count=0 |
| 2 | 1 | 2 | 查 **0 → 1 次** | **count=1** ✅ | **count=0** ❌ |
| 3 | 1 | 3 | 查 1 → 1 次 | **count=2** ✅ | count=1 ❌ |

**正确答案 2，漏掉那行变成 1。**

### 为什么是 `map.put(0, 1)` 而不是 `map.put(0, 0)`

那个"不存在的第 0 个前缀和"，代表**子数组的起点可以是下标 0**。

它的「出现次数」是 1——**因为空前缀只存在一次。**

> 如果写成 `map.put(0, 0)`，等于说"这个前缀和没出现过"，那从下标 0 开始的子数组就永远找不到。

## 易错点清单

| # | 坑 | 后果 |
|---|---|---|
| 1 | **用滑动窗口做有负数的子数组题** | 单调性失效，逻辑无解 |
| 2 | **忘写 `map.put(0, 1)`** | 从头开始的子数组全漏 |
| 3 | 写成 `map.put(0, 0)` | 同上 |
| 4 | 存的是下标而不是次数 | `count` 会变成"能不能找到"而不是"有几个" |
| 5 | **先 `merge` 再查** | 会把自己算进去（`pre - k == pre` 当 k=0 时出错） |
| 6 | `while` 里用不变的 `i` 累加 | 元素为 0 时死循环 |

### 第 5 条细说

顺序是**先查、后记**——和两数之和的「先查后存」完全一致。

```java
count += map.getOrDefault(pre - k, 0);   // ① 先查
map.merge(pre, 1, Integer::sum);         // ② 后记
```

反了的话，`k = 0` 时 `pre - k == pre`，自己会匹配到自己。

## 手推验证

`nums = [1,-1,1]`, `k = 1`（含负数，滑窗救不了的例子）

| 步 | x | pre | 查 `pre-1` | count | map 更新后 |
|---|---|---|---|---|---|
| 初始 | — | 0 | — | 0 | `{0:1}` |
| 1 | 1 | 1 | 查 0 → 1 | **1** | `{0:1, 1:1}` |
| 2 | -1 | 0 | 查 -1 → 0 | 1 | `{0:2, 1:1}` |
| 3 | 1 | 1 | 查 0 → **2** | **3** | `{0:2, 1:2}` |

**结果 3** ✅（子数组 `[1]`、`[1]`、`[1,-1,1]` 各自和为 1）

## 一句话总结

> **子数组和 = 两个前缀和相减。所以问题变成「`pre - k` 这个前缀和出现过几次」——这就是两数之和。**
