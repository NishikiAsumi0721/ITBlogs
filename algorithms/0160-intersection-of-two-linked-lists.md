## 题目

给你两个单链表的头节点 `headA` 和 `headB`，请你找出并返回两个单链表相交的起始节点。如果两个链表不存在相交节点，返回 `null`。

```
输入：A = [4,1,8,4,5], B = [5,6,1,8,4,5]
输出：节点 8（值 8 的那个节点，不是 index 8）
```

> **关键**：返回的是**节点对象**，不是值。比较必须用 `==`（引用相等），不能用值。

---

## 我的版本（能过，但空链表误判）

```java
public class Solution {
    public ListNode getIntersectionNode(ListNode headA, ListNode headB) {
        ListNode p = headA;
        ListNode q = headB;

        while (p != null || q != null) {
            if (p == null) p = headB;
            if (q == null) q = headA;
            if (p == q) return p;
            p = p.next;
            q = q.next;
        }
        return null;
    }
}
```

### ✅ 思路是对的

**「走完自己的链表，转去走对方的链表」**——两边走的总步数都变成 `a + b`，如果长度不同，这一步就抹平了差值。

**LeetCode 官方示例、等长不相交、B 是 A 的后缀，三种都能过。**

### ❌ 空链表会误判

**A 为空、B 非空：**

```
初始：p = null, q = B0

while: (null != null → false) || (B0 != null → true) → 进入
if(p == null) p = headB;   → p = B0
if(q == null)            → q 不是 null，不动，q 还是 B0
if(p == q)               → B0 == B0 → 返回 B0  ❌
```

**空链表和任何链表都不可能有交点，但这里返回了 B0。**

**B 为空、A 非空**同理：`q` 重置成 `headA`，如果 `p` 正好在 `headA` 位置，立刻误判。

### 为什么误判

> **「重置」和「推进」是分开的。**
>
> `p` 被重置那一轮，**`q` 还在原处没动**——两个指针在同一个位置撞上，但那是**重置碰巧重合**，不是真交点。

---

## 正确写法

```java
public class Solution {
    public ListNode getIntersectionNode(ListNode headA, ListNode headB) {
        ListNode p = headA, q = headB;

        while (p != q) {
            p = (p == null) ? headB : p.next;
            q = (q == null) ? headA : q.next;
        }
        return p;
    }
}
```

### 为什么这版空链表是对的

**用三元表达式，把「重置」和「推进」合成一个动作——每轮必进一步。**

再推空 A：

```
p = null, q = B0
while (null != B0) → 进入
p = (null == null) ? headB : p.next   → p = B0
q = (B0 == null) ? headA : q.next     → q = B0.next   ← ★ q 前进了！

下一轮：while (B0 != B0.next) → 不会再撞
```

**关键差别：`q` 前进了。**

我的版本里 `q` 不是 null，所以**没动**——两个指针都停在 `B0`，才撞上。

### 三处改进对照

| | 我的写法 | 标准写法 |
|---|---|---|
| 循环条件 | `p!=null \|\| q!=null` | **`p != q`** |
| 每轮推进 | 只在"没重置"时推进 | **每轮无条件进一步** |
| 重置时机 | 先重置 → 比较 → 推进 | **重置即前进，比较在下一轮顶上** |
| 空链表 | ❌ 误判 | ✅ 正确 |
| 行数 | 12 行 | **8 行** |

### 为什么 `p != q` 这个条件能正常退出

**无交点时**：`p` 走 `a+b` 步、`q` 走 `b+a` 步，**同时变成 `null`** → `null == null` → 退出，返回 `null`。

**有交点时**：两者走的步数相同，会在交点处相遇。

> **这个性质成立，但需要推一遍才敢用。**
> 而 `p != q` 这个写法**不需要这个前提就能退出**——因为每轮必进一步，最终都会到 null。

---

## ★ 三个关键点

### ① 比较的是引用，不是值

```java
if (p == q) return p;   // ✅ 引用相等
if (p.val == q.val)     // ❌ 值相等不代表同一节点
```

**题目问的是"相交的起始节点"，是同一个对象，不是值相同。**

### ② 交叉走为什么能抹平长度差

```
A 长 a，B 长 b，公共部分长 c

p 走：a（A 独有 + 公共） → 转去 B → 再走 b
q 走：b → 转去 A → 再走 a

两条路径总长都是 a + b，所以同时到达交点。
```

**长度差被"走对方的链表"抵消掉了。**

### ③ 为什么不用哈希

**哈希也能做**：把 A 的所有节点放进 Set，遍历 B 找第一个在 Set 里的。**O(a+b) 时间、O(a) 空间。**

**双指针的优势是 O(1) 空间**——面试问"能不能不用额外空间"，答案就是它。

## 易错点清单

| # | 坑 | 后果 |
|---|---|---|
| 1 | **重置和推进分开** | 空链表时两指针在重置点重合 → **误判** |
| 2 | 用 `p.val == q.val` 比较 | 值相同但不是同一节点 → 误判 |
| 3 | 重置成 `headB.next` 而不是 `headB` | 漏掉 B 的头节点 |
| 4 | 忘记返回 `null`（无交点时） | 编译不过 |
| 5 | 返回 `p.next` 而不是 `p` | 偏离一个节点 |

## 手推验证

**有交点**：A = `[4,1,8,4,5]`，B = `[5,6,1,8,4,5]`，公共尾 `[8,4,5]`

| 步 | p | q |
|---|---|---|
| 1 | 4 | 5 |
| 2 | 1 | 6 |
| 3 | 8 | 1 |
| 4 | 4 | **8** |
| 5 | 5 | 4 |
| 6 | **null → 转过 B → 5** | 5 |
| 7 | 6 | **null → 转过 A → 4** |
| ... | ... | ... |

**两条路都走 3+3=6 步后，在节点 `8` 相遇。**

**无交点、等长**：同时变 null → 退出 → 返回 null ✅

---

## 一句话总结

> **走完自己的转去走对方的，长度差就被抹平了。**
> **但重置和推进要合成一个动作——分开写的话，空链表会在重置点误判相遇。**
