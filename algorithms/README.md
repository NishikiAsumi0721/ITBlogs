## 记录格式

每道题一个 md 文件，命名 `题号-题名.md`，包含：

| 字段 | 说明 |
|---|---|
| 难度 | 简单 / 中等 / 困难 |
| 我的解法 | 自己第一版写出来的代码 |
| 复杂度 | 时间 / 空间 |
| 不足 | 这版哪里不够好 |
| 更优解 | 标准答案，附关键代码 |
| **关键洞察** | 一句话说清"这题的转折点在哪" |
| 易错点 | 我踩过或差点踩的坑 |

## 已踩过的坑（跨题汇总）

| 坑 | 出现在 | 说明 |
|---|---|---|
| `new List<>()` | 三数之和 v1 | 接口不能实例化，用 `ArrayList` |
| `res.add(list)` 存引用 | 两数之和、三数之和 | 必须 `new ArrayList<>(list)` 存副本 |
| 循环条件写反致 NPE | — | `fast != null && fast.next != null` 顺序不能反 |
| **找到答案就 break** | 三数之和 v5 | 求「全部答案」的题必须穷尽 |
| **去重放循环开头** | 三数之和 v5 | 应放在命中之后 |
| 用 for + 独立 if 代替 while | 三数之和 v4 | 双指针要反复移动，`if` 只判一次 |
| **边界判断写在取值后面** | 移动零 | `nums[left]!=0 && left<n` 应先判 `left<n` |
| **手动搜索位置导致处处越界** | 移动零 v1-v2 | 改成「收集非零」，边界问题消失 |
| 为防越界人为缩一格 | 移动零 v3 | 改用自然的 `length` |
| 写了永远执行不到的死代码 | 移动零 v3 | `if (right >= n) break` 恒不成立 |

## 三档标记法

每道题做完标一档，复习时只刷「见过」和「不会」：

- **会** —— 不看题解能默写
- **见过** —— 记得思路，写不全
- **不会** —— 看完题解也没完全理解

> 同一个专题刷 20 题「见过」，不如 8 题「会」。
