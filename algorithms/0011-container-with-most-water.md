## 题目

给定一个长度为 `n` 的整数数组 `height`。有 `n` 条垂线，第 `i` 条线的两个端点是 `(i, 0)` 和 `(i, height[i])`。

找出其中的两条线，使得它们与 `x` 轴共同构成的容器可以容纳最多的水。返回容器可以储存的最大水量。

```
输入：[1,8,6,2,5,4,8,3,7]
输出：49
```

---

## 我的解法（通过，第一版）

```java
class Solution {
    public int maxArea(int[] height) {
        if (height.length == 0 || height.length == 1) return 0;   // ⚠️ 多余，见下文
        int left = 0;
        int right = height.length - 1;
        int max1 = 0;
        while (left < right) {
            max1 = Math.max(((right - left) * Math.min(height[left], height[right])), max1);
            if (height[left] <= height[right]) { left++; }
            else if (height[left] > height[right]) { right--; }   // ⚠️ 可简化成 else
        }
        return max1;
    }
}
```

### 复杂度

| 项 | 值 |
|---|---|
| 时间 | **O(n)** —— 每个元素只被访问一次 |
| 空间 | **O(1)** |

### 验证

`height = [1,8,6,2,5,4,8,3,7]`

| 步 | left | right | 面积 | max |
|---|---|---|---|---|
| 1 | 0(1) | 8(7) | 8×1 = 8 | 8 |
| 2 | 1(8) | 8(7) | 7×7 = **49** | **49** |
| 3 | 1(8) | 7(3) | 6×3 = 18 | 49 |
| 4 | 1(8) | 6(8) | 5×8 = 40 | 49 |
| 5 | 2(6) | 6(8) | 4×6 = 24 | 49 |

**结果 49 ✅**

## ★ 核心：为什么必须移动较矮的那一边

**这道题的价值不在代码，在这个证明。** 面试问「这段代码为什么对」，答不出来就证明在背模板。

### 面积公式里，谁决定上限

```
面积 = (right - left) × min(h[left], h[right])
                        ↑
                    较矮的那边决定高度
```

**较矮的那条边，是当前容器的瓶颈。**

### 反证：移动较高的那一边会怎样

假设 `h[left] < h[right]`（左边矮），现在去移动**右边**（高的那边）：

| 变化 | 结果 |
|---|---|
| 宽度 `right - left` | **一定变小**（right 左移了） |
| 高度上限 | **还是 `h[left]`**（矮的那条没动，瓶颈没变） |
| 面积 | **只会变小或不变** |

**移动高边，亏两次：宽度少了，高度没有改善。**

### 正解：移动较矮的那一边

移动**左边**（矮的那边）：

| 变化 | 结果 |
|---|---|
| 宽度 | 变小 |
| 高度上限 | **有可能变高**（新来的边可能比原来的矮边更高） |
| 面积 | **有可能变大** |

**只有移动矮边，才有机会找到更大的容器。**

### 一句话记住

> **移动高的那边：短板没变，宽度还少了——亏两次。**
> **移动矮的那边：宽度少了，但可能换来更高的板。**

**这就是贪心选择成立的理由。**

## 三道双指针题：移动规则完全不同

同样叫「对撞双指针」，但**决定动哪个指针的依据不一样，不能混用**。

| 题 | 双指针类型 | 移动依据 |
|---|---|---|
| [三数之和](0015-three-sum.md) | 对撞 | 看**和的大小**：和偏小 → 左移；和偏大 → 右移 |
| **盛最多水** | **对撞** | 看**两边高度比**：**永远动矮的那边** |
| [移动零](0283-move-zeroes.md) | 同向（快慢） | 快的扫描，慢的写入 |

**关键区别**：

- 三数之和：`nums[left] + nums[right]` 是**要凑的目标**，所以看「和」是偏大还是偏小
- 盛水：`min(h[left], h[right])` 是**当前的瓶颈**，所以要「换掉瓶颈」→ 动矮的

**一个是"凑数"，一个是"突破瓶颈"。思维模型不同。**

---

## 两处可以改进（不影响正确性）

### 1. 多余的 guard ★见 [代码习惯：习惯性加防御](00-代码习惯-习惯性加防御.md)

```java
if (height.length == 0 || height.length == 1) return 0;   // ❌ 永远不起作用
```

**不写它，代码自己也能正确处理**：

| 长度 | left | right | `while(left<right)` |
|---|---|---|---|
| 0 | 0 | **-1** | `0 < -1` → false，返回 0 |
| 1 | 0 | 0 | `0 < 0` → false，返回 0 |

**`while(left<right)` 本身就是最自然的边界保护。**

### 2. `else if` 可以简化

```java
if (height[left] <= height[right]) { left++; }
else if (height[left] > height[right]) { right--; }   // 条件必然成立
```

第一个条件覆盖了 `<=`，`else` 必然是 `>`。写成 `else` 更清楚，也少一处「读者要再推一遍」的地方。

### 清理后

```java
class Solution {
    public int maxArea(int[] height) {
        int left = 0, right = height.length - 1;
        int maxArea = 0;

        while (left < right) {
            int h = Math.min(height[left], height[right]);
            maxArea = Math.max(maxArea, (right - left) * h);

            if (height[left] <= height[right]) left++;
            else right--;
        }
        return maxArea;
    }
}
```

12 行，没有一行是多余的。

## 关键洞察

> **容器的容量由短板决定。所以每次都要「换掉短板」，而不是换长板。**

这个思维模型可以迁移到别处：**任何"由最弱环节决定整体上限"的问题，优化方向都是提升最弱的那一环。**
