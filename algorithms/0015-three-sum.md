## 题目

给你一个整数数组 `nums`，判断是否存在三元组 `[nums[i], nums[j], nums[k]]` 满足 `i != j`、`i != k` 且 `j != k`，同时还满足 `nums[i] + nums[j] + nums[k] == 0`。

请返回所有和为 `0` 且**不重复**的三元组。

```
输入：nums = [-1,0,1,2,-1,-4]
输出：[[-1,-1,2],[-1,0,1]]
```

---

## 最终解法（通过）

```java
class Solution {
    public List<List<Integer>> threeSum(int[] nums) {
        List<List<Integer>> res = new ArrayList<>();
        Arrays.sort(nums);                                   // ★ 排序是前提

        for (int i = 0; i < nums.length - 2; i++) {
            if (nums[i] > 0) break;                          // 剪枝：最小的都 > 0
            if (i > 0 && nums[i] == nums[i - 1]) continue;   // ① i 去重

            int left = i + 1;
            int right = nums.length - 1;

            while (left < right) {                           // ★ 必须是 while
                int sum = nums[i] + nums[left] + nums[right];

                if (sum < 0) {
                    left++;                                  // 和偏小 → 换更大的 → 左指针右移
                } else if (sum > 0) {
                    right--;                                 // 和偏大 → 换更小的 → 右指针左移
                } else {
                    res.add(Arrays.asList(nums[i], nums[left], nums[right]));

                    while (left < right && nums[left] == nums[left + 1]) left++;     // ② left 去重
                    while (left < right && nums[right] == nums[right - 1]) right--;  // ③ right 去重

                    left++;                                  // ★ 继续找下一组，不能 break
                    right--;
                }
            }
        }
        return res;
    }
}
```

### 复杂度

| 项 | 值 |
|---|---|
| 时间 | **O(n²)** —— 排序 O(n log n) + 外层 n × 双指针 O(n) |
| 空间 | O(log n) ～ O(n)（排序用） |

## 六版演进（这才是这题的价值）

### v1：三层 for 暴力

```java
for (i) for (j=i+1) for (q=j+1) { if (sum==0) ... }
```

**问题**：
- `new List<Integer>()` —— **接口不能 new，编译不过**
- `result.add(list)` 存引用，后面 list 变了，结果全废
- 去重用 `equals` 比 List —— **顺序敏感**，`[-1,0,1]` 和 `[0,-1,1]` 认不出来
- O(n³)，n=3000 必超时

### v2：固定 i 和末尾，p 扫中间

**问题**：`j` 定义后**从没变过**——右端恒等于 `nums[n-1]`。
→ 只覆盖了「包含最后一个元素」的三元组，其他全没看。

### v3：加了 b 循环枚举右端点

**问题**：
- **O(n³)**（i × b × p 三层）
- `p < b - 2` **少一位**：`[-1,0,1]` 这种最基础的 case 直接返回空
- `list` 在 p 循环里只加不减，存进去的是 4-5 个元素的乱列表

### v4：有 while 的雏形，但三个独立 if

**问题**：
- **缺 `while (left < right)`** —— 每个 i 只检查 1~2 次就过去了
- 三个独立 `if` 串行判断，第一条改了指针，第二条又拿新值算
- `left++` 无边界检查 → `nums = [-1,-1,0]` 时 **数组越界崩溃**

### v5：while 有了，`break` 又错了

```java
else if (sum == 0) {
    res.add(list);
    break;              // ❌
}
```

**问题**：同一个 i 可能有**多个**答案，`break` 只找第一个。

`[-1,0,1,2,-1,-4]` → 只输出 `[[-1,-1,2]]`，**丢掉 `[-1,0,1]`**。

另外：去重 `while` 放在**算 sum 之前**——会跳过还没判断过的位置。

### v6：通过 ✅

改动清单：
1. `break` → `left++; right--;`
2. 去重 `while` 从「循环开头」挪到「命中之后」
3. `nums[0] > 0` → `nums[i] > 0`

## 关键洞察

> **三数之和 = 排序 + 固定一个数 + 剩下两数用双指针。**

### 为什么必须排序？两个理由

| 理由 | 说明 |
|---|---|
| **双指针前提** | 左右夹逼依赖有序：和偏小就左移、偏大就右移，这个单调性只有有序才成立 |
| **去重变简单** ★ | 排序后相同值相邻，"跳过重复"就变成"和上一个比" |

**第二个理由才是主因。** 用哈希做三数之和，去重会极其麻烦——`[-1,0,1]` 和 `[0,-1,1]` 是两次不同的循环，都进结果集。

### 为什么双指针能省掉一层循环

假设 `nums[i] + nums[left] + nums[right] < 0`：

- 和偏小，要让和变大
- **`right` 已经是最大的了**，只能让 `left` 往右移（换更大的数）
- 所以 **`(left, right' < right)` 这一整片组合都不用试了**

**一个大小判断，砍掉一整层枚举。** 这就是 O(n³) → O(n²) 的来源。

### 和两数之和的根本差别

| | 两数之和 | 三数之和 |
|---|---|---|
| 解法 | **哈希表** | **排序 + 双指针** |
| 原因 | 只需找一对，O(n) 最优 | 要枚举 n 个固定值，每个再找一对；**排序顺带解决去重** |
| 去重 | 不需要 | **必须，且是难点** |

---

## 三个去重位置（缺一不可）

排序后相同值相邻，所以去重 = "遇到和上一个相同的，跳过去"。

### ① i 去重 —— 放在外层开头

```java
if (i > 0 && nums[i] == nums[i - 1]) continue;
```

`nums = [-1,-1,0,1]`，i=0 和 i=1 都是 `-1`，会产出两次 `[-1,0,1]`。

### ② left 去重 / ③ right 去重 —— 放在命中之后

```java
if (sum == 0) {
    res.add(...);

    while (left < right && nums[left] == nums[left + 1]) left++;
    while (left < right && nums[right] == nums[right - 1]) right--;

    left++;
    right--;
}
```

**为什么必须放命中之后**：放循环开头的话，还没判断 sum 就先跳过了指针，可能跳过唯一能凑成 0 的位置。

## 易错点清单（按我实际踩过的顺序）

| # | 坑 | 后果 |
|---|---|---|
| 1 | `new List<Integer>()` | 编译不过（接口不能实例化） |
| 2 | `res.add(list)` 存引用不存副本 | 所有结果被最后一次修改污染 |
| 3 | 右指针定义后不移动 | 只覆盖一部分组合 |
| 4 | 用 `for` + 三个独立 `if` 代替 `while` + `if/else if` | 每轮只判一次，大片组合漏掉 |
| 5 | **`break` 找到第一组就退出** | 同一 i 的后续答案全丢 |
| 6 | **去重 `while` 放在算 sum 之前** | 跳过未判断的位置 |
| 7 | `left++` 无边界检查 | 数组越界崩溃 |
| 8 | `nums[0] > 0` 当剪枝 | 剪枝失效（应该看 `nums[i]`） |

**第 5 条最隐蔽**：`break` 的思维来自两数之和（"找到一个就返回"），但三数之和是**求全部答案**，必须穷尽。

**两个"不能"**：

> **不能 `break`** —— 找到一组要继续找，双指针内移
> **去重不能放前面** —— 先算 sum，命中之后再跳过重复值

## 手推验证（复习时默写这遍）

`nums = [-1, 0, 1, 2, -1, -4]` → 排序后 `[-4, -1, -1, 0, 1, 2]`

| i | nums[i] | left | right | sum | 动作 |
|---|---|---|---|---|---|
| 0 | -4 | 1(-1) | 5(2) | -3 | left++ |
| 0 | -4 | 2(-1) | 5(2) | -3 | left++ |
| 0 | -4 | 3(0) | 5(2) | -2 | left++ |
| 0 | -4 | 4(1) | 5(2) | -1 | left++ → 5，退出 |
| 1 | -1 | 2(-1) | 5(2) | **0** | ✅ `[-1,-1,2]`，内移 |
| 1 | -1 | 3(0) | 4(1) | **0** | ✅ `[-1,0,1]`，内移 |
| 1 | -1 | 4 | 3 | — | 退出 |
| 2 | -1 | — | — | — | i 去重跳过 |
| 3 | 0 | 4(1) | 5(2) | 3 | right--，退出 |

**结果 `[[-1,-1,2], [-1,0,1]]` ✅**

## 一句话总结

> **排序一次，同时解决「双指针要有序」和「去重」两个问题。找到答案不要 break，把双指针内移继续找。**
