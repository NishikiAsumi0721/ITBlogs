## 题目

给定一个整数数组 `nums` 和一个整数目标值 `target`，请你在该数组中找出**和为目标值** `target` 的那**两个**整数，并返回它们的数组下标。

可以假设每种输入只会对应一个答案，且不能重复使用相同的元素。

```
输入：nums = [2,7,11,15], target = 9
输出：[0,1]
解释：因为 nums[0] + nums[1] == 9，返回 [0, 1]
```

---

## 我的解法：暴力双重循环

```java
class Solution {
    public int[] twoSum(int[] nums, int target) {
        for (int i = 0; i < nums.length; i++) {
            for (int j = i + 1; j < nums.length; j++) {
                if (nums[i] + nums[j] == target) {
                    int[] list = new int[2];
                    list[0] = i;
                    list[1] = j;
                    return list;
                }
            }
        }
        return null;
    }
}
```

### 复杂度

| 项 | 值 |
|---|---|
| 时间 | **O(n²)** —— 两层循环，最坏遍历 n(n-1)/2 次 |
| 空间 | **O(1)** —— 只用了两个循环变量和一个结果数组 |

### 这版做对的地方

- `j = i + 1` —— 从 i 之后开始，避免了「自己和自己相加」和「重复配对」，这个边界处理是对的
- 找到即返回，没有多余遍历

### 不足

| # | 问题 | 说明 |
|---|---|---|
| 1 | 时间复杂度 O(n²) | `n = 10⁴` 时约 5×10⁷ 次比较，本题能过但已接近上限；再大一个数量级就超时 |
| 2 | 变量名 `list` 不准确 | 是数组不是 List，叫 `result` 更清楚 |
| 3 | 数组初始化啰嗦 | 可以一行完成：`return new int[]{i, j};` |
| 4 | 返回 `null` | 题目保证有解，走不到这里；但返回 `null` 不如返回空数组，调用方少一个判空 |

## 更优解：哈希表一次遍历

```java
class Solution {
    public int[] twoSum(int[] nums, int target) {
        // key: 数组元素的值, value: 该元素的下标
        Map<Integer, Integer> seen = new HashMap<>();

        for (int i = 0; i < nums.length; i++) {
            int need = target - nums[i];

            // 先查：这个"另一半"之前出现过吗？
            if (seen.containsKey(need)) {
                return new int[]{seen.get(need), i};
            }

            // 后存：把自己放进去，供后面的人查
            seen.put(nums[i], i);
        }

        return new int[]{};
    }
}
```

### 复杂度

| 项 | 值 |
|---|---|
| 时间 | **O(n)** —— 每个元素只看一次，哈希表查询是 O(1) |
| 空间 | **O(n)** —— 最坏情况所有元素都进哈希表 |

**这是一次典型的空间换时间**：多用了 O(n) 的哈希表，把时间从 O(n²) 降到 O(n)。

---

## 关键洞察

> **不要问「哪两个数加起来等于 target」，要问「对于每个数，它需要的那另一半，之前出现过吗」。**

两个视角的差别：

| 视角 | 做法 | 复杂度 |
|---|---|---|
| 两两组合 | 枚举所有 (i, j) 组合，看和是不是 target | O(n²) |
| **换个角度** | 遍历每个数，查「target − 当前数」是否已出现 | O(n) |

**这个转换是整类题的原型**：凡是「找一对/一组满足某种关系」的题，都可以试着把「枚举组合」换成「查表找补数」。后面的三数之和、四数之和，都是从这儿长出来的。

---

## 易错点

### ⚠️ 最容易踩的坑：先查还是先存？

代码里必须是**先查 `seen`，再把当前元素 `put` 进去**。

如果顺序反了：

```java
// ❌ 错误顺序
seen.put(nums[i], i);          // 先把自己存进去
if (seen.containsKey(need)) {  // 再查
    return new int[]{seen.get(need), i};
}
```

反例：`nums = [3, 3], target = 6`

| 步骤 | 错误写法 | 正确写法 |
|---|---|---|
| i = 0 | `put(3, 0)`，然后 `need = 3`，`seen` 里有 3 → 返回 **[0, 0]** ❌ | `need = 3`，`seen` 为空 → `put(3, 0)` |
| i = 1 | 走不到 | `need = 3`，`seen` 有 3 → 返回 **[0, 1]** ✅ |

**`[0, 0]` 意味着同一个元素用了两次**，直接违反题目要求。

> 本质原因：题目说「不能重复使用相同的元素」，而「先存」等于允许当前元素和自己配对。

### 其他

- **返回顺序无所谓**：`[0, 1]` 和 `[1, 0]` 都算对，LeetCode 会规范化
- **有重复值时**：`seen.put(nums[i], i)` 会覆盖旧下标。但因为题目保证只有一个答案，且有答案时会在 `put` 之前就 `return`，所以不影响正确性
- **数组可能是负数**：不用特殊处理，哈希表天然支持

## 两种解法对比

| | 暴力 | 哈希表 |
|---|---|---|
| 时间 | O(n²) | **O(n)** |
| 空间 | O(1) | O(n) |
| 代码量 | 短 | 稍长 |
| 适用 | n 很小（< 1000） | n 大，通用 |
| 面试答法 | 先说这个，再主动给优化 | 作为最终答案 |

**面试建议**：先讲暴力思路（1 分钟说清），再主动说「可以用哈希表降到 O(n)」。这样展示的是思考过程，不是背答案。
